# Importaciones y exportaciones
Menú Project

* Exports

##  Exportar el libro de códigos

Esta es una opción del menú Project > Exports.

Un libro de códigos es una lista de sus códigos. El memo de cada código debería detallar las razones de la finalidad de cada código. El libro de códigos puede exportarse a un archivo de texto. El libro de códigos también muestra la frecuencia de uso de los códigos (de todos los codificadores). Como los códigos y las categorías se disponen en una estructura de árbol, el doble guion '–' indica los códigos y categorías subordinados dentro de una categoría.

## Importar el libro de códigos

Importe un libro de códigos como archivo de texto plano (.txt) o como archivo .csv. Use dos símbolos de mayor que para separar categoría y código.

### Texto plano

Use el tabulador para añadir luego un memo.
```
code1

category1>>category2>>code2	memo

category1>>code3

category3>>code4
```

### CSV

Las categorías y los códigos van en la primera columna. Los memos de los códigos, si los hay, van en la segunda columna.
```
code1

category1>>category2>>code2

category3>>code3
```

##  REFI-QDA
[Rotterdam Exchange Format Initiative (REFI)](https://www.qdasoftware.org)  es un estándar abierto para exportar e importar libros de códigos y proyectos desde y hacia distintos programas de análisis cualitativo de datos asistido por computadora.

Actualmente, QualCoder puede importar un libro de códigos siempre que use la versión "urn:QDA-XML:codebook:1.0". QualCoder exporta también en esta versión.

La exportación y la importación de un proyecto son funcionales. Todavía no estoy preparado para garantizar que cumplan plenamente el estándar REFI-QDA, en particular algunos aspectos de audio y video. Se ha experimentado un poco con archivos de proyecto REFI_QDA de Nvivo, Atlas.ti, Quirkos y MAXQDA. La importación en MAXQDA parece requerir un carácter adicional de fin de línea en lo relativo a la codificación de texto: esta es una opción en la exportación de proyectos REFI-QDA de QualCoder. La importación en Atlas.ti desplazó las codificaciones un carácter después de cada fin de línea, y aún no se ha resuelto. La importación de atributos desde QualCoder no funciona en Atlas.ti ni en MAXQDA; los atributos de caso no se importaron en Quirkos.

Características como los conjuntos y los grafos no pueden importarse, ya que esa funcionalidad no está en QualCoder. Otros formatos de datos no se conservan; por ejemplo, una fecha o un booleano se convertirían en datos de texto. 

Para audio y video, la importación de transcripciones y puntos de sincronización no está probada. La importación o vinculación de archivos con vínculos relativos no se ha probado.

Para importar, cierre primero cualquier proyecto que esté abierto. Luego elija un nombre nuevo de proyecto de QualCoder y seleccione el archivo qdpx que va a importar.

Si no se ve ningún dato codificado, puede que necesite cambiar el nombre del codificador actual en la Configuración. Pruebe con la lista desplegable de nombres de codificador.

Esto ya es antiguo (febrero de 2021), pero un usuario probó la importación de un archivo de proyecto REFI-QDA generado por QualCoder e importado en MAXQDA, Quirkos y Atlas.ti. Solo se probaron texto e imágenes. Aquí hay un PDF con los resultados de la prueba: [Testing importation of REFI-QDA Project files into Atlas, MAXQDA, Quirkos PDF](https://qualcoder.files.wordpress.com/2021/02/refi-qda-project-import-quirkos-maxqda-atlas.pdf)

## RQDA
Los proyectos creados con [RQDA](http://rqda.r-forge.r-project.org/) pueden importarse directamente. Se importan todos los datos salvo las categorías de archivos.

Cierre cualquier proyecto abierto. Luego, en el menú principal, en Project, haga clic en RQDA Project import. Se le pedirá crear un proyecto nuevo, así que introduzca un nombre. Después se le pedirá seleccionar el archivo de proyecto de RQDA. QualCoder importará entonces los datos.

Si no se ve ningún dato codificado, puede que necesite cambiar el nombre del codificador actual en la Configuración. Pruebe con la lista desplegable de nombres de codificador.

## Taguette
Los proyectos creados con [Taguette](https://www.taguette.org/) pueden importarse directamente. Todos sus datos básicos de codificación se transferirán.

Cierre cualquier proyecto abierto. Luego, en el menú principal, en Project, haga clic en Taguette Project import. Se le pedirá crear un proyecto nuevo, así que introduzca un nombre. Después se le pedirá seleccionar el archivo de proyecto de Taguette (normalmente con extensión .sqlite3). QualCoder procederá entonces a importar los datos.

Si no ve ningún dato codificado, puede que necesite cambiar el nombre del codificador actual en la Configuración. Pruebe usando la lista desplegable de nombres de codificador.

## Importar una encuesta

Esto requiere un archivo CSV o de Excel (formato xlsx). Puede probar a importar el archivo survey.csv de la carpeta Examples.

Los archivos de encuesta en formato CSV están delimitados por comas; puede elegirse otro delimitador. Para archivos delimitados por tabuladores escriba ta, tb o tab en el cuadro Delimiter para que QualCoder sepa que el archivo csv está delimitado por tabuladores. **La primera fila debe contener los encabezados de los atributos. La primera columna debe contener los identificadores únicos de cada persona encuestada.**

El formato de entrecomillado del CSV puede ser NONE, MINIMAL o ALL. A continuación se muestran ejemplos de cada uno; por favor, abra su archivo CSV con un editor de texto o similar para comprobar cómo se ha preparado.

```
NONE

colin, 44, male

MINIMAL

"colin", 44, "male"

ALL

"Colin", "44", "male"
```

QualCoder determinará si las demás columnas (atributos) son numéricas o de tipo carácter. Para las columnas numéricas, cada celda debe contener un número, ya que incluso las entradas en blanco harán que se tome como carácter de forma predeterminada.

QualCoder no puede determinar si un atributo es un dato cualitativo. Debe hacer clic derecho y cambiar el tipo de campo de carácter a cualitativo en aquellos campos que deban ser cualitativos. 

![image](https://github.com/user-attachments/assets/ae540730-b58c-484e-9beb-8aa40093e94d)

La opción predeterminada es que cada respuesta cualitativa de cada fila se almacene en su propia entrada de archivo de texto en la base de datos de QualCoder. Este archivo se adjuntará a cada caso (cada entrada de fila de la encuesta, con el ID único)

Al hacer clic en el botón OK, se añadirán los casos y sus atributos. 

### Versiones anteriores de QualCoder, por ejemplo QualCoder 3.5.
Cada respuesta a una pregunta cualitativa se añadía a UN único archivo de texto. Antes de la respuesta había texto adicional añadido por QualCoder para indicar a qué caso correspondía la respuesta. 

Con este formato: _[unique id] The qualitative text._

Abra Manage Files, luego visualice ese archivo y verá el texto de asignación al caso subrayado en verde.

## Importar bibliografía

Importe una bibliografía. Debe estar en texto plano con formato RIS. El archivo puede tener extensión .txt o .ris

En el menú, vaya a Manage > Manage references. Presione el botón de importar: tiene el icono de una flecha sobre un documento.

Seleccione el archivo.

La pestaña Action Log mostrará cuántas referencias se importaron.

Una vez importadas, vaya al menú: Files and Cases > Manage references.

Aquí puede vincular (y desvincular) referencias a archivos. Puede editar manualmente una referencia importada. Puede eliminar una referencia.

Una vez importada y con los archivos vinculados a las referencias, vaya a la pantalla Manage Files.
Aquí habrá cuatro columnas de atributos nuevas: Ref_Authors, Ref_Title, Ref_Type, Ref_Year

Los archivos vinculados a referencias tendrán detalles en esas columnas.

## Ayuda - Funciones especiales

### Actualización dinámica del contenido de texto

Esto es útil para actualizar archivos de texto, como extractos de entradas de blog, que cambian con el tiempo. Actualiza un archivo de texto intentando conservar los segmentos de texto codificados existentes. Seleccione el archivo de texto que debe reemplazarse y seleccione el archivo de reemplazo. Haga clic en el botón de los engranajes para ejecutar la actualización. Esta función opera localizando el texto idéntico coincidente en el archivo de reemplazo a medida que recorre el texto del archivo. Puede producir segmentos codificados de forma errónea.

### Fusionar proyectos de QualCoder

Seleccione un proyecto de QualCoder para fusionarlo (proyecto de origen) en el proyecto actualmente abierto (proyecto de destino), y luego haga clic en el botón de engranajes _Run merge projects_. **Antes de realizar la fusión, haga una copia de seguridad del proyecto de destino.**

Advertencia: si cada proyecto que se va a fusionar tiene el mismo nombre de codificador, por ejemplo 'default', entonces se fusionarán como tales y no podrá distinguir qué codificador realizó su propia codificación. Esto puede ser o no una consideración importante para su proyecto fusionado final.

Ocurre lo siguiente:

* Copia los archivos no coincidentes de las carpetas del proyecto de origen a las carpetas del proyecto de destino.
* Añade las categorías de origen nuevas (no coincidentes) a la base de datos de destino.
* Añade los nombres de código de origen nuevos (no coincidentes) a la base de datos de destino.
* Añade los diarios y stored_sql a la base de datos de destino, solo si tienen nombres que no coinciden con los nombres existentes en el destino.
* Añade las codificaciones de texto, las anotaciones de texto, las codificaciones de imagen y las codificaciones de A/V a la base de datos de destino.
* Añade los casos y case_text (vínculos de los casos a segmentos de archivos de texto, imágenes y A/V).
* Añade los atributos de archivos y casos.
* Añade los valores de los atributos. Los valores de atributo existentes en el destino no se sobrescriben, salvo que estén en blanco.

!!! info "Consideraciones antes de fusionar"
    Idealmente, todos tendrían los mismos archivos idénticos dentro del proyecto.
    Idealmente, usando el mismo conjunto de nombres de código, aunque esto podría resolverse después si se fusionan o renombran códigos en el proyecto reunido.
    Nombres de codificador: tendrían que ser únicos para cada codificador. Así, al reunirlo todo, el trabajo de cada codificador puede identificarse.
    Como alternativa, los nombres de codificador podrían ser los mismos, siempre que cada codificador trabajara en archivos distintos. Pero todo eso depende, en realidad, de sus objetivos finales. Por si tuviera necesidad de reunirlo todo bajo un único nombre de codificador.

!!! warning "Advertencias al fusionar"
    La advertencia principal se da si el proyecto de origen y el de destino contienen el mismo archivo de texto. Si el archivo de texto del proyecto de origen ha sido editado y puede ser más largo o más corto, entonces las posiciones de codificación y las anotaciones importadas serán incorrectas. Esto se debe a que el texto del archivo original del proyecto de destino almacenado en la base de datos no se reemplaza por el archivo de texto editado del proyecto de origen.
