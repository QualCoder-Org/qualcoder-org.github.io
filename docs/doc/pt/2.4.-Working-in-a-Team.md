# Trabalhar juntos em uma equipe
Existem várias estratégias para organizar trabalho colaborativo no mesmo projeto em QualCoder. Escolha o que melhor se adequa à sua abordagem metodológica e ambiente de trabalho específico.

## 1) Edição sequencial do mesmo projeto
Essa abordagem pode ser aplicada tanto na codificação indutiva quanto na dedutiva. Baseia-se no princípio de que todos os membros da equipe trabalham nos mesmos arquivos do projeto, embora não simultaneamente.

** Coordenação da Sequência do Trabalho: **

* Você pode fazer isso via e-mail para que cada pessoa, ao completar suas tarefas, envie a pasta de projeto zipped para o indivíduo subsequente na lista.
* Você também pode trabalhar sequencialmente no mesmo computador, usando a mesma pasta de projeto.
* Se você coordenar o trabalho manualmente, usar um serviço de compartilhamento de nuvem como OneDrive ou Dropbox para transferir os arquivos também é uma opção. No entanto, é crítico que a) em nenhuma circunstância duas pessoas acessem o mesmo projeto simultaneamente, e b) o projeto deve ser totalmente sincronizado com o serviço de nuvem antes de passar o trabalho para o próximo indivíduo. A pessoa sucesso deve também garantir que tenha baixado a versão mais recente da nuvem antes de iniciar suas tarefas. Tenha cuidado: As versões do projeto que saem de sincronia podem corromper seus dados, e você então tem que reverter para uma cópia de backup.
* Por favor, não use a exportação do Projeto REFI-QDA como uma abordagem de rotina para colaboração quando todos os codificadores estão usando o QualCoder. Use uma das outras opções descritas aqui. Se você precisa abrir um projeto em software diferente (por exemplo, Taguette, NVivo, Atlas.ti, MAXQDA, Dedoose, Quirkos), só então você deve usar a exportação do Projeto REFI-QDA. Os recursos do projeto podem ser perdidos ao transferir um projeto entre software qualitativo usando a exportação do Projeto REFI-QDA.

Lidar com os nomes do codificador cuidadosamente (ver abaixo).

## 2) Usando um Projeto Mestre: A Abordagem de 'Codificação Separada Depois Mesclagem'

Essa estratégia permite que sua equipe trabalhe simultaneamente até certo ponto. É mais eficaz se você usar uma abordagem de codificação dedutiva, onde o sistema de código não muda muito durante a análise. Se você usá-lo com codificação indutiva, esteja preparado para passar algum tempo limpando e consolidando o sistema de código ao fundir o trabalho de diferentes membros da equipe.


Siga estes passos:

* Criar um projeto mestre com o sistema de código já definido (se aplicável).
* Idealmente, importar todos os documentos empíricos nesta fase. Evite vincular a arquivos externos, pois isso complica a distribuição do projeto.
* Feche sua pasta de projeto, incluindo todas as subpastas e arquivos, e envie para seus colaboradores (e-mail, transferência de arquivos ou USB-stick).
* Decida sobre uma estratégia para lidar com nomes de codificadores em sua equipe, como explicado nas notas abaixo.
* Agora, cada membro da equipe pode descompactar sua cópia local do projeto e trabalhar nele de forma independente, adicionando códigos, codificação, memorandos, etc. No entanto, não edite o texto importado dos próprios documentos empíricos, uma vez que isso pode causar problemas durante o processo de fusão mais tarde.
* Finalmente, reúna todas as cópias locais e misture-as sequencialmente em seu projeto mestre, usando o [processo descrito aqui](6.1.-Imports-and-Exports#merge-qualcoder-projects).

## Considerações importantes sobre nomes de codificadores

* Na maioria dos casos, você deseja ter um nome único para cada codificador em sua equipe para que as contribuições individuais possam ser identificadas mesmo após a fusão do projeto.
* No Projeto > Configurações, clique no botão "Alterar" ao lado do nome do codificador para abrir uma janela onde você pode alterar sua própria identidade ou criar, renomear ou mesclar outros codificadores dentro do projeto atual.

![Janela do codificador](/images/380291b1-6e34-4bd3-8344-182af8448140.png)

(Note que a codificação do alto-falante é usada internamente para marcar automaticamente enunciados do alto-falante em transcrições. Este nome não deve ser usado para outros fins.)

* Tenha cuidado, especialmente com a função Mesclar, pois não há Desfazer. Se você cometer um erro enquanto estiver na tela de nomes do codificador, pressione o botão cancelar e as alterações serão revertidas. Depois de clicar em OK, as alterações são permanentes. No entanto, a função merge fará uma cópia do seu projeto antes da merge com um sufixo  pre coder merge .
* Na mesma janela, você pode controlar a visibilidade de outros colaboradores. Desde a versão 3.8 do QualCoder, as contribuições de outros codificadores são sempre visíveis e editáveis por padrão, a menos que você escolha o contrário. Esconder outros colaboradores é especialmente útil para medir a confiabilidade intercodificador, o que requer que várias pessoas codificem o mesmo documento sem influenciar umas às outras.
* Esta janela também é acessível a partir da barra de ferramentas no texto de código, imagem de código e espaço de trabalho PDF código, embora com opções limitadas.

!!! warning
    Não mantenha a pasta do projeto em uma unidade de rede ou em uma localização na nuvem, e acesse essa localização enquanto executa o Qualcoder. Se a conexão do banco de dados for perdida, ele corromperia o banco de dados enquanto o QualCoder está realizando uma série de operações de banco de dados.

## Cópias de segurança

Faça um backup da pasta do projeto antes de fazer quaisquer alterações substanciais, como uma reorganização substancial de códigos e categorias, projetos de fusão ou códigos de fusão. O QualCoder realiza backups por hora (mantendo até os cinco mais recentes, se os backups estiverem definidos nas configurações). Além disso, não armazenar arquivos extras ou saídas dentro da pasta do projeto.

Além disso, para boas práticas de gerenciamento de dados, você deve ter um cronograma de backup regular para seu trabalho e também fazer backup do projeto para diferentes dispositivos ou unidades.
